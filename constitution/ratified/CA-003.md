# 1. Purpose
This amendment establishes the canonical constitutional definition of Context within the Zyppi Reality Model (ZRM).

Multiple workstreams reference Context in different operational capacities:
- Intent Resolution
- Contract Selection
- Authority Scope
- Jurisdiction Determination
- Temporal Validity
- Hierarchy Interpretation

These usages are valid and non-conflicting.

However, no constitutional document currently defines Context as a unified concept.

This amendment resolves that gap.

# 2. Constitutional Definition
## CA-003-01 — Context Definition
> Context is the collection of conditions, constraints, scopes, and environmental factors that influence the interpretation, routing, validation, authorization, prioritization, or execution of a constitutional object.

Context modifies meaning.

Context does not create meaning.

Context provides the circumstances under which constitutional entities, relationships, transactions, contracts, events, outcomes, and authorities are evaluated.

# 3. Context Is Not A Constitutional Primitive
### CA-003-02 — Non-Primitive Status
Context SHALL NOT be classified as:
- a Constitutional Primitive
- a Registry Cluster
- a Constitutional Entity Family
- a Root Taxonomy

Context exists only as a modifier of constitutional objects.

Context SHALL NOT exist independently without a governing constitutional object.

# 4. Context Ownership Model
### CA-003-03 — Distributed Ownership
Context is a constitutional concept.

Context is not owned by a single cluster.

Each Context Domain is owned by the cluster responsible for the underlying reality being described.

**Ownership SHALL follow the principle:**
> The cluster that owns the reality owns the context governing that reality.

# 5. Canonical Context Domains
The Zyppi Reality Model recognizes four constitutional Context Domains.

No additional Context Domains may be introduced without constitutional amendment.

## Domain 1 — Execution Context
### Purpose
Defines the conditions used when selecting, evaluating, or executing Intent Contracts.

**Examples**
Location
Language
Device
Audience Segment
Campaign Context
Operating Environment
Market Conditions

### **Primary Usage**
- Intent Resolution
- Contract Selection
- Execution Routing

### **Governing Cluster**
- CL-16 Intelligence

- WS-01
- WS-03A.5

# 6. Hierarchy Context Clarification
## CA-003-04
Hierarchy classification context referenced in WS-03A.2 SHALL NOT be considered a separate Context Domain.

Hierarchy Context is merely an interpretation mechanism used by:
- Taxonomy Relationships
- Containment Relationships
- Genealogy Relationships

and therefore remains governed by the Relationship Framework.

No additional Context Domain is created.

# 7. Campaign Context Clarification
## CA-003-05
**As established by CA-002:**
Campaign Context is classified as Execution Context.

Campaign Context SHALL be owned by CL-16 Intelligence.

Campaign Context SHALL NOT be treated as:
- a Campaign Identity
- a Campaign Entity
- a Constitutional Primitive

Campaign Context exists solely as an execution-scoping modifier.

# 8. Context Registry Prohibition
## CA-003-06
The ZRM SHALL NOT introduce:
- Context Registry
- Context Cluster
- Context Entity Family

Creating standalone Context objects would violate the Reality-First principle by promoting environmental modifiers into first-class realities.

Context SHALL remain attached to constitutional objects that require contextual interpretation.

# 9. Canonical Context Envelope
## CA-003-07
Implementations MAY construct Context Envelopes as operational structures.

A Context Envelope MAY aggregate:
- Execution Context
- Authority Context
- Temporal Context
- Jurisdictional Context
for evaluation purposes.

The Context Envelope is an implementation construct.

It is not a constitutional object.

It does not require registry ownership.

# 10. Constitutional Interpretation Rule
## CA-003-08
Whenever the term "Context" appears in future constitutional documents, the term SHALL be interpreted according to the Unified Context Model defined in this amendment.

Authors SHOULD explicitly identify which Context Domain is being referenced whenever ambiguity may exist.

# 11. Constitutional Effects
**This amendment:**
- ✓ Resolves CIA-02 Finding CR-004
 - ✓ Establishes a unified constitutional definition of Context
 - ✓ Clarifies ownership boundaries
 - ✓ Prevents future Context inflation
 - ✓ Preserves Reality-First modeling principles
 - ✓ Clarifies Campaign Context ownership under CA-002
 - ✓ Eliminates need for a Context Registry

# Ratification Result
Context is hereby recognized as a constitutional modifier with four canonical domains:
- Execution Context
- Authority Context
- Temporal Context
- Jurisdictional Context

No Context Registry, Context Cluster, or Context Primitive shall exist within the Zyppi Reality Model.
